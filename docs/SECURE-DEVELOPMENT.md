# Regras para o desenvolvimento (12)

| Requisito                        | Implementação                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 12.1 ambientes separados         | `APP_ENV`, `DATABASE_URL`, `AUDIT_DATABASE_URL` e `BACKUP_TEST_DATABASE_URL` distintos; `pnpm check:env` exige `APP_ENV=production`, `DEV_TEAM_PRODUCTION_ACCESS=false`, bases diferentes e HTTPS/TLS≥1.2. Sem credencial de dev em produção (7.4).                                                                                               |
| 12.2 dados fictícios             | Seeds e testes sintéticos; `scripts/check-fixtures.ts` varre CPF/RG/telefone/cartão/token em arquivos de seed/teste (check `fixtures` no CI e em `pnpm verify`).                                                                                                                                                                                  |
| 12.3 OWASP                       | Prisma parametrizado, Zod em todas as entradas, saída escapada, cookies `HttpOnly`/`SameSite`/`Secure`, `trustedOrigins` e challenge 2FA consumido + uso único (`totp-single-use.ts`), cabeçalhos CSP/HSTS/X-Frame-Options/nosniff/Referrer-Policy em `next.config.ts`, autorização server-side em rotas **e páginas**, `accountLockout` 5/15min. |
| 12.4 sem segredos no repositório | `.env.example` sem valores reais; `pnpm check:secrets` varre arquivos versionados; `pnpm check:env` valida o cofre; check `secrets` no CI.                                                                                                                                                                                                        |
| 12.5 code review                 | `.github/CODEOWNERS` exige revisão; `scripts/check-branch-protection.ts` verifica via `gh api` a proteção da `main` (PR + 1 aprovação + checks obrigatórios), check `governance` no CI; entrega por PRs.                                                                                                                                          |
| 12.6 dependências                | `pnpm audit --prod --audit-level high` (check `dependencies`) + `.github/dependabot.yml` com atualizações semanais de npm e GitHub Actions.                                                                                                                                                                                                       |
| 12.7 erros genéricos             | `jsonError` mapeia erros sem expor stack ou detalhes internos; login usa mensagem única.                                                                                                                                                                                                                                                          |

O CI (`ci.yml`) orquestra **um workflow reutilizável por check** (`check-*.yml`), cada um com status check próprio no PR: Conventional Commits, format, lint, Biome, typecheck, testes, cobertura, build, secret scan, auditoria de dependências, validação de ambiente de produção, schema/migrações Prisma, fixtures e governança. Executa também semanalmente (`schedule`) e manualmente (`workflow_dispatch`).

Todos os workflows e os git hooks versionados em `.github/hooks/` usam a mesma fonte de comandos (`.github/hooks/checks.sh`), instalável com `pnpm hooks:install` — veja `.github/hooks/README.md`. Isso garante que a validação local seja idêntica à do CI. O antigo push automático de formatação foi substituído pelo `pre-commit` local, tornando todos os checks do CI somente-leitura.
