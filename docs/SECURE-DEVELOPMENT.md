# Regras para o desenvolvimento (12)

| Requisito                        | Implementação                                                                                                                                                                                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 12.1 ambientes separados         | `NODE_ENV`, `DATABASE_URL` e `AUDIT_DATABASE_URL` distintos por ambiente; `pnpm check:env` falha cedo em produção. Desenvolvedores não têm credencial de produção (7.4).                                                                                                                        |
| 12.2 dados fictícios             | Seeds e testes usam apenas dados sintéticos; nenhum dump real é versionado.                                                                                                                                                                                                                     |
| 12.3 OWASP                       | Prisma parametrizado, Zod em todas as entradas, saída escapada, cookies `HttpOnly`/`SameSite`/`Secure`, `trustedOrigins` e challenge 2FA consumido (CSRF), cabeçalhos CSP/HSTS/X-Frame-Options/nosniff/Referrer-Policy em `next.config.ts`, autorização server-side e `accountLockout` 5/15min. |
| 12.4 sem segredos no repositório | `.env.example` sem valores reais; `pnpm check:secrets` varre arquivos versionados; job `security` no CI.                                                                                                                                                                                        |
| 12.5 code review                 | Entrega por PRs com CI obrigatório; nenhum push direto na branch protegida.                                                                                                                                                                                                                     |
| 12.6 dependências                | `pnpm audit --prod --audit-level high` no job `security`; atualizações acompanhadas pelo lockfile.                                                                                                                                                                                              |
| 12.7 erros genéricos             | `jsonError` mapeia erros sem expor stack ou detalhes internos; login usa mensagem única.                                                                                                                                                                                                        |

O CI (`ci.yml`) orquestra **um workflow reutilizável por check** (`check-*.yml`), cada um com status check próprio no PR: Conventional Commits, format, lint, Biome, typecheck, testes, cobertura, build, secret scan, auditoria de dependências, validação de ambiente de produção e schema/migrações Prisma. Executa também semanalmente (`schedule`) e manualmente (`workflow_dispatch`).

Todos os workflows e os git hooks versionados em `.github/hooks/` usam a mesma fonte de comandos (`.github/hooks/checks.sh`), instalável com `pnpm hooks:install` — veja `.github/hooks/README.md`. Isso garante que a validação local (12.5, code review assistido) seja idêntica à do CI. O antigo push automático de formatação foi substituído pelo `pre-commit` local, tornando todos os checks do CI somente-leitura.
